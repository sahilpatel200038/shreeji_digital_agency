## Deploying

1. `npm install`
2. `npm run build`. It applies the migration through `scripts/migrate.mjs`. If the host's connection cap stops that step, the build still continues, so run `npm run db:deploy` yourself before starting the app: the public blog list and the post editor read `Post.thumbnailMediaId`, and until the migration is applied they fail with the "database is missing tables" message.
3. Restart the Node app and check `/api/health`.

## Known limits

- Converting an old post to rich text turns its FAQ and call-to-action blocks into headings/paragraphs/links (the FAQ accordion and FAQ structured data are lost for that post). Posts that are not re-saved are unchanged.
- Rich text supports no tables, fonts or font sizes (deliberately: they would fight the site's typography).
- Settings-style screens without a parent list (Header, Footer, Home page, Contact page, Menus, SEO, Settings) have no Back button.
- Images uploaded in the editor are not deleted from the media library if the author removes them from the post (they stay in the library for reuse).
